# 增量语法索引

代码检索仍默认 off。启用 lexical/structure 后先对完整已准入工作区做轻量词法排序，再在 200 文件 / 2 MiB 的解析预算内选择文件；查询命中或已知相关的后部路径不再因字典排序落在预算之后。没有扩大工作区准入额度，也不宣称完整仓库语义图。

Worker 的进程内缓存按 `(tenant, run, path)` 隔离，用原始文件摘要和解析器版本验证 AST/符号/导入 metadata；未变文件复用、变更文件重新解析、删除文件移除，导入边始终按当前文件集合重新计算。条目上限 1,024，metadata 序列化字节加开销预估上限 8 MiB；不是 Python RSS 硬限制。缓存不含原始源码、不落盘，返回深拷贝，等待、暂停、终结或擦除状态在释放量子时清空任务缓存；没有租约的任务被控制 API 暂停或擦除时，下一次领取轮询也回收该任务缓存。跨进程不共享缓存，重启后重新构建；权限与输入摘要仍在付费派发前复核。

`scripts/profile-code-index.py --output <报告>` 的 1,201 文件合成测量中，cold 解析 200 文件，warm 解析 0 文件，单文件变更解析 1 文件；三次均命中排序末端的目标文件。原始报告：`benchmarks/reports/incremental-code-index-2026-10-10.json`。耗时约 110/91/89ms，仅三次机制样本，不能当作修复率、费用收益或稳定延迟增益。

检索清单增加 eligible_files、scanned_bytes、parsed_files、cache_hits 与选择策略；保留 skipped_count 和显式未解析文件。结构邻接仍是预算内视图，动态导入、包别名与类型推导未支持。完整图、LSP 与大于当前工作区额度的仓库需另有任务证据后升级。
