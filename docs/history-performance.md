# 历史增长与本地测量

0009 增加持久 workspace revision。数据库约束触发器在提交阶段推进租户计数，同一事务合并一次，回滚不生效；API 只读该租户一行并绑定调用者身份，不再对多个业务表聚合字符串或全量任务版本。触发器覆盖 Run、动作、预算、审批、产物、项目、知识、评测、设置和授权变化。提交阶段的单租户计数仍会串行化短暂写入；它不是无限并发方案，写争用需另测。

事件重建在 SQL 中限定状态、schema、范围和指定 checkpoint，然后排序 LIMIT 1；0009 有对应索引。记忆先筛 active 与 project，再在同一治理锁语义下作相关性和冲突判断。未引入未经证实需要的向量数据库。运维健康检查在 SQL 聚合并只返回每项最多 100 个 ID，`ids_truncated` 提示明细不完整。

任务创建将 archive、基线和验收对象发布移到租户知识生命周期锁之前；提交前重新检查授权，再固定技能和记忆。重复请求仍受各自幂等键锁保护。同步 service 调用仍在数据库事务中，因此尚不能宣称所有对象 I/O 均在事务外；当前先缩短全租户治理锁范围，后续用真实 S3/锁等待测量决定是否引入两阶段发布。

执行：`uv run python scripts/measure-history.py --history 1000 --samples 20 --concurrency 4 --output benchmarks/reports/history-read-path-2026-10-09.json`。脚本创建独立 pilot 租户，保留 1,001 个 checkpoint 和 1,000 条不活动记忆；20 次读路径组合包含 revision、rebuild、memory retrieve、operations health。报告保存主机/Python/PostgreSQL信息、并发、P50/P95、采样锁等待和连接数；不调用模型，不执行仓库代码。

这是共享本机上的读路径 pilot。采样可能漏掉瞬时等待，没有旧实现同硬件对照、真实恢复或写负载结果，因此不声称吞吐提升倍数、生产 P95 或 SLO 达标。当前实现支持重新测量 100/1,000/5,000 历史量和 1–8 并发。负结果也应保留。

2026-10-09 本机样本：20 次、4 并发，组合 P50 919.67 ms、P95 1,015.04 ms，采样锁等待 0、连接峰值 4。主机曾观测 CPU 100%，与调度时限失败共同说明当前共享环境不能用于证明生产容量。原始样本保存于 `benchmarks/reports/history-read-path-2026-10-09.json`。
