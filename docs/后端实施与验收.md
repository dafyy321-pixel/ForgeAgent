# 后端实施与验收

更新：2026-09-24。版本：0.2.0。依据为《ForgeAgent 完整优化方案》《资料核查与选型依据》，前端保留 Forge Marks 规范。

## 交付边界

原前端的浏览器模拟已由 FastAPI + PostgreSQL + 独立 Worker 取代。任务执行、文件快照、预算、审批、远程任务句柄、验收、产物和评测均有服务端实现。

**不能将这次交付表述为完整方案全部验收通过。** 以下矩阵区分代码实现、契约测试与尚缺的生产/研究工作。没有凭测试 fixture 推断真实模型能力、协议互操作成功或生产安全性。

## 实际执行链路

1. API 在同一事务保存 TaskSpec、Run、SemanticManifest、初始检查点与调度 job；相同 Idempotency-Key 不重复创建任务，参数不同会拒绝。
2. Worker 领取租约，固定 epoch，检查当前权限和版本，编译上下文，预留费用并记录模型请求。
3. 模型结果通过结构校验后，逐项记录动作意图。外部写入进入审批，派发前再检查当前授权与效果摘要。
4. 本地读写在该 epoch 的独立文本目录进行；命令只能在 Docker 内执行。完整快照成功存储后才提交其引用。
5. 模型提议完成后，Verifier 使用固定验收契约检查冻结版本，保存 patch、summary 与 verification.json。成功须有 PASS 和对应摘要证据。
6. 用户可按序号续读 SSE、查看原始观察、对账、暂停、取消、恢复或 fork。审计 replay 不调用模型与工具。

## 外部输入投递的崩溃处理

MCP 输入响应先写 outbox，派发前将记录转为 dispatching。超时或 Worker 中断后将其转为 unknown，同时阻止重新派发对应动作。控制台支持：

- “核对输入投递”：确认这条输入是否送达，恢复原远程任务的状态查询；这不代表整个远程任务完成。
- “提交对账处置”：对整个远程动作的最终效果作人工确认，并保存证据。

只有确认输入未发生后，才允许用户显式重新提交该输入。审批拒绝/过期后重新审查会创建新的 Action 和 Approval；旧授权不会被复用。

## 评测语义

任务集绑定不可覆盖的项目基线与验收摘要。每个 case 有 task、预算、权限和预期处置；预期 PAUSED/FAILED 必须预先给定原因代码。数据集分 development 或 held_out。

配对实验每配置使用同一模型设置及安全边界，排程按固定随机种子打散。支持 `harness.context_policy=full|elide`、`harness.memory`、`harness.observation_recall` 与技能列表。总任务硬预算之和不得超过提交者声明的实验费用上限。

统计对每个 case 先合并重复，再按 case 聚类 bootstrap 1,000 次。少于两个独立 case 不生成配对区间，也不能认为非劣证据成立。未结算费用保持 awaiting_reconciliation。完成后固化结果快照；之后另行恢复暂停任务不会重写旧实验的已固化结果。

技能发布需要非 fixture 的 held-out 实验：至少 20 个 case、两个项目、三次重复，候选配置包含该技能而基线不包含，配对区间和成本比例满足预先登记阈值。发布还需人工审核说明。这里没有声称“20 个 case 足以证明任意非劣界”，也没有独立远端效果 oracle；生产安全门禁仍需专门验证。

## 测试与环境

本次使用真实本地 PostgreSQL、非超级用户应用账号、Python 3.12 和 Chromium。测试结果及浏览器截图位于 `test-results/`，HTML 报告位于 `playwright-report/`。

后端最终结果：**75 passed，3 skipped**。3 项跳过均为需要 Docker 的真实容器测试，另有 2 条第三方依赖弃用警告。Ruff 检查与前端生产构建通过。浏览器最终结果：**5 passed**，检查 1440、720、390 像素宽度，并人工查看了桌面、手机和验收页截图。

验收命令：

```sh
uv run alembic upgrade head
uv run ruff check backend tests/backend migrations
uv run pytest tests/backend -q
npm run build
npm run test:ui
```

Docker 专项测试在 `tests/backend/test_sandbox.py`；设置 `FORGE_TEST_DOCKER=1` 后检查真实容器非 root/只读/网络边界、超时清理和独立验收。CI 配置会构建镜像并启用这些测试。本机由于 Docker 不可用而跳过，不计为通过。

没有在本次工作中调用付费模型、向真实 MCP/A2A 端点发送副作用、推送代码、发布包或部署外网服务。协议测试使用可控响应和故障注入。

## 运维操作

`GET /v1/operations/health` 或 `uv run forge admin health` 返回过期租约、未知效果、过期审批、未知账单、异常 outbox、暂停任务及处理说明。

`uv run forge admin gc` 预览本地孤儿对象；`--apply` 才执行回收。要求至少 24 小时宽限，只处理已结束且已释放租约的任务目录，扫描全部持久 JSON 引用，保留事件、验收和历史检查点引用。活跃任务、尚未成功创建的任务目录和 S3 对象均不在自动回收范围。回收不会删除历史证据，也不是用户数据彻底删除接口。

| 情况 | 处理 |
| --- | --- |
| MODEL_NOT_CONFIGURED | 配置模型 ID/密钥/价格，重启 API 和 Worker，对旧任务显式绑定后恢复 |
| SANDBOX_UNAVAILABLE | 修复 Docker/WSL2，构建镜像，在恢复页面重新检查环境 |
| SEMANTIC_DRIFT | 使用新尝试/fork；不要篡改旧 manifest 或伪装旧 Worker |
| UNKNOWN 动作或输入 | 查询提供方并录入证据；禁止凭超时推断失败或自动重发 |
| 未知模型账单 | 使用提供方账单进行预算对账；无法确认时保留预留 |
| 数据库不可用 | 恢复数据库连接后等待租约接管；不允许先在内存里继续派发效果 |
| 对象缺失/损坏 | 从备份恢复对应摘要对象，或创建新尝试；不要绕过摘要校验 |
| 审批失效 | 重新发起当前版本审查，重新检查能力、参数与资源版本 |

生产接入前仍需处理矩阵中的未完成项，尤其是版本升级策略、备份恢复、对象保留/删除、项目级授权、真实模型和远端协议联调、资源总量限制与规模压测。
